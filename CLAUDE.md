## Project Overview

PureAdminIcons is a Phoenix 1.8 / LiveView web application that aggregates SVG icons from multiple icon libraries (FluentUI System Icons, Font Awesome Free, Heroicons, Lucide Icons, Tabler Icons) into a searchable catalog. It provides a web UI for browsing/searching icons, a JSON API, and a sync pipeline that downloads, parses, and imports icons into a PostgreSQL database.

## Common Commands

- **Setup:** `mix setup` (installs deps, builds assets)
- **Dev server:** `mix phx.server` or `iex -S mix phx.server`
- **Pre-commit checks:** `mix precommit` (runs in test env)
- **Run all tests:** `mix test`
- **Run single test file:** `mix test test/path/to_test.exs`
- **Run previously failed tests:** `mix test --failed`
- **Build assets:** `mix assets.build`
- **Deploy assets:** `mix assets.deploy`
- **Format code:** `mix format`

## Architecture

### Database Layer (`lib/database/`)

Auto-generated by **db-gen** — do not manually edit these files. `Database.DbContext` calls PostgreSQL stored procedures/functions. Each DB function has a matching model (struct) in `models/` and a result parser in `processors/`.

The import pipeline uses PostgreSQL stage tables:
1. Bulk-insert raw data into `stage.icon` and `stage.icon_phrase` via COPY
2. Call `stage.process_icon_import()` which handles create/update/delete and synonym linking

### Sync System (`lib/pure_admin_icons/sync/`)

- **`Adapter` behaviour** — each icon set implements `download/0`, `parse/1`, `move_svgs/2`, `cleanup/1`
- **Adapters** in `sync/adapters/` for fluentui, font_awesome, heroicons, lucide, tabler
- **`Worker`** orchestrates full sync: download → parse → stage insert → DB import → SVG storage
- **`SvgDownloader`** handles HTTP downloads and zip extraction
- Dev caching available via `:use_icon_cache` config to avoid re-downloading

### Scheduled Jobs

Quantum scheduler (`PureAdminIcons.Scheduler`) runs:
- Daily icon sync at 3 AM
- Daily metrics cube refresh at 4 AM

### Web Layer (`lib/pure_admin_icons_web/`)

- **Main UI:** `IconSearchLive` — icon search/browse LiveView at `/`
- **API:** `API.IconController` at `/api/icons/search`, `API.HealthController` at `/api/health`
- **Icon files:** `IconFileController` serves SVG files at `/icons/:icon_set/:style/:filename`
- **Docs:** LiveViews under `Docs.*` at `/docs/*`
- Uses DaisyUI + Tailwind for styling

### Key Modules

- `PureAdminIcons.Icons` — context module for icon queries
- `PureAdminIcons.RateLimiter` — Hammer-based rate limiting
- `PureAdminIcons.SearchMetricsCollector` — batches search tracking calls

## Guidelines from AGENTS.md

All Phoenix 1.8 and Elixir guidelines in AGENTS.md apply. Key points:

- Use `Req` for HTTP requests — never use HTTPoison, Tesla, or httpc
- LiveView templates must begin with `<Layouts.app flash={@flash} ...>`
- Use the `<.icon name="hero-x-mark">` component for icons, never Heroicons modules
- Use `<.input>` component for form inputs
- Always use LiveView streams for collections
- Use `to_form/2` for forms, never pass changesets directly to templates
- Elixir lists don't support index access — use `Enum.at/2`
- Never nest multiple modules in the same file
- Local config overrides via `config/{env}.local.exs` (gitignored)
